 초록
 피싱 웹사이트 분류의 정확도를 높이기 위해 많은 입력 특징을 활용하는 접근은 직관적이지만, 실제 환경에서는 정보 접근성·추출
 의존성이 서로 다르다. 이 연구는 URL 표기에서 얻는 8개 특징만으로 학습한 로지스틱 회귀와, SSL 인증서 상태를 추가한 9개 특징,
  그리고 원본이 제공하는 전체 30개 특징을 동일한 실험 조건으로 비교하였다. 2015년 공개된 UCI Phishing Websites의
 11,055건에서 결정적 난수 절차로 선택한 450건(피싱 183, 정상 267)을 사용하였다 [1].

 완전히 동일한 입력 벡터 23건의 학습·검증 중복 누출을 막기 위해 427개 고유 벡터를 그룹으로 취급하는 5-분할 교차검증을 실시
 하고, 모든 검증 표본의 OOF(out-of-fold) 예측을 합쳐 평가하였다. 피싱 클래스 F1은 URL 8특징에서 0.688, URL+SSL 9특징
 에서 0.875, 전체 30특징에서 0.914였다. 전체와 URL 8특징의 F1 차이는 0.226이고 고정 OOF 예측에 대한 그룹 부트스트랩
 95% 구간은 0.171~0.284였다.

 결과는 이 역사적 표본에서 URL 표기 특징만으로 얻은 분류 성능이 전체 특징 사용 시보다 낮았다는 연구가설을 지지한다. 다만 데
 이터에 실제 URL·수집 시점이 없으므로 도메인·시간 기반 외부 검증이 불가능하다. 특히 과거 SSL 신호의 효과를 현재 웹 환경의
 효과로 일반화해서는 안 된다.

 핵심어 피싱 탐지, 정보보안, 로지스틱 회귀, 특징 제거 실험, 재현성, 데이터 누출



 1. 연구 배경 및 문제 정의
 피싱 사이트는 계정·인증정보의 탈취를 노리는 대표적인 웹 위협이다. 탐지 모델에 어떤 데이터를 입력할 것인가는 성능뿐 아니라
 수집 가능성과 적용 범위를 좌우한다. URL 문자열 기반 신호는 페이지 내부 HTML이나 외부 서비스 데이터에 비해 활용 조건이 단
 순할 수 있다. 반면 데이터 소스가 제한되면 분류에 필요한 정보가 빠질 수도 있다. 기존 선행연구는 URL·페이지·외부정보의 조합
 과 데이터셋의 재현성 문제를 지적하였다 [2,3].

 따라서 동일 데이터, 동일 분류기, 동일 검증 구조로 특징 종류만 변경하는 통제 비교가 필요하다. 이 연구는 시간·데이터 수급 환경
 을 고려하여 실제 공격 수행이나 웹사이트 접속 대신 공개된 비식별 특징 원자료만 분석한다.

 2.1 연구 질문 · 가설 · 반증 가능 조건

 RQ. URL 표기 기반 특징 8개만 사용한 로지스틱 회귀와 전체 30개 특징을 사용하는 같은 로지스틱 회귀 사이에 피싱 양성 F1 차이
 가 있는가?

 H1(연구가설). 전체 30개 특징의 F1이 URL 8개 특징보다 0.05를 초과해 높다(ΔF1 > 0.05). H0. ΔF1 ≤ 0.05. 이는 분석 전에
 기록한 기술적 판정 기준이며 형식적인 모집단 유의성 검정으로 사용하지 않는다.

 반증 조건. 관측된 ΔF1이 0.05 이하이거나 부트스트랩 구간이 경계와 넓게 겹치면 이 데이터에 한정한 H1 지지가 약하다고 판단
 한다. 이후 탐색적으로 SSL 특성 하나를 추가한 조건도 분석하되 핵심 H1에 포함해 재정의하지 않는다.

 4. 실험 설계와 평가 절차
 특징 집합 이외의 조건을 고정했다. 알고리즘은 로지스틱 회귀(C=1.0, solver=liblinear, max_iter=2000), 특징 값은 학습 폴드
 안에서만 OneHotEncoder로 처리했다. 테스트 폴드에 맞춘 전처리나 임계값 조정은 하지 않았고, 양성 판정 확률 임계값은 0.5이
 다.

 450개 중 동일한 30특징 벡터를 가진 사례는 검증 때 같은 그룹에 속하도록 한 뒤, StratifiedGroupKFold(5개 폴드,
 shuffle=True, random_state=42)로 평가했다. **모든 평가 숫자는 5개 검증 폴드의 예측을 이어붙인 OOF 결과**이며 모델의
 학습 적합도(training score)가 아니다. 그룹 분리는 일치 벡터 누출만 제어한다. 실제 도메인 식별자가 없으므로 같은 사이트의 다
 른 벡터가 양측에 걸칠 가능성은 제거하지 못한다.

 주요 지표는 피싱을 양성으로 한 F1(정밀도와 재현율의 조화평균)이고, 정확도·균형정확도·정밀도·재현율·ROC-AUC 및 혼동행
 렬을 함께 기록한다. 주요 비교의 차이는 ΔF1=F1(ALL30)-F1(URL8)이며, 재현 가능한 2,000회 그룹-쌍 부트스트랩으로
 OOF 예측의 차이 구간을 계산한다. 이 구간은 모델 재학습 변동까지 포괄하는 일반화 신뢰구간이 아니다.


 4.1 실제 검증 조치와 데이터 변경 기록

  • 데이터 전체 특징 행의 중복 23건 발견 → 동일한 특징 벡터가 학습/검증 양측에 들어가지 않도록 그룹 분할 적용.

  • URL 표기 특징 8개와 URL 외 SSL 신호를 구분 → SSL 추가 9개 조건을 별도 탐색 결과로 보고.

  • 전체 입력 450건 검증 후 중복 23건을 제거한 427건으로 민감도 검증 추가. 새로운 데이터를 모은 것으로 표시하지 않음.

  • 코드·원자료·OOF 예측·메트릭·그림·실행 버전 고정, 패키지 안에 포함.

 5.2 반대 가능성 및 민감도 분석
 만약 URL8이 ALL30과 비슷한 F1을 얻었다면 추가 특징에 따른 복잡성을 정당화하기 어렵다는 반대 결과가 나왔을 것이다. 실제
 결과는 반대였다. 반면 추가 특징의 순기여는 동일하지 않았다. URL8에 SSLfinal_State만 추가해도 F1은 0.688 → 0.875로 상
 승했고, 남은 21개를 포함한 ALL30은 0.875 → 0.914로 늘어났다. 따라서 “모든 추가 특징이 동일하게 기여한다”는 강한 해석은
 자료가 지지하지 않는다.

 중복 벡터 23건을 제거한 427건으로 다시 층화 5-fold를 실행했을 때 URL8 F1=0.702, URL8+SSL9 F1=0.873, ALL30
 F1=0.911이었다. ALL30-URL8 차이 0.209로 방향이 유지되었다. 이것은 같은 450개 표본의 민감도 분석이지 독립적인 외부 테
 스트셋은 아니다.



 6. 해석과 논의

 6.1 가설에 대한 판정

 450개 표본의 그룹 교차검증에서 사전 기준 ΔF1>0.05를 관측값 0.226이 넘었으며, OOF 고정 부트스트랩 95% 구간의 하한
 (0.171)도 그보다 높았다. 따라서 이 자료와 통제된 모델 비교에서는 H1을 지지한다. 논문에서 관측하지 않은 실시간 처리 속도,
 도메인 보안 성능, 신규 캠페인 탐지율은 결론의 범위에 포함하지 않는다.


 6.2 SSL 특징의 해석 주의

 URL8에 SSLfinal_State 하나만 추가했을 때 F1이 0.187 상승한 점은 해당 표본에서 인증서 관련 신호가 매우 구별력 있는 변수였
 다는 것을 시사한다. 하지만 이 데이터는 2015년에 공개되었고, 인증서 배포 관행과 피싱 기술은 변화해 왔다. 예컨대 SSL 인증서
 존재 자체가 현재 사이트 신뢰성을 보증한다는 의미는 아니다. 따라서 2015년 데이터에서의 영향력을 2026년 사이트의 실제 효과
 로 확대하지 않는다.

 6.3 연구의 한계와 잠재적 반론

  • 역사적 표본 편향 — 공개 원본 11,055건 중 무작위 450건만 분석했다. 원자료 수집 시기와 오늘의 피싱 캠페인이 다르며 표본 신
    뢰구간도 전체 2026 모집단으로 외삽할 수 없다.

  • 도메인·시점 정보 부재 — 실제 URL/도메인/수집일이 없어 그룹 분할은 완전히 동일한 30특징 벡터만 묶을 수 있다. 완전한 도메
    인-분리와 시간-분리 평가를 수행할 수 없다 [3].

  • 특징 추출 비용 미측정 — URL 문자열·SSL·도메인/외부정보는 접근 요건이 다르나 이 실험은 모델 추론/특징 수집 시간과 네트
    워크 비용을 측정하지 않았다. URL8을 “빠르다”고 실증 주장하지 않는다.

  • 외부 유효성 부족 — 다른 시점·다른 사이트·다른 수집기관의 외부 데이터에 대한 평가가 없다. 현재 보안 제품 성능 또는 실전 도
    입 적합성을 검증한 것은 아니다.

  • 라벨/특성 설계 — 원본이 제작한 휴리스틱 규칙과 클래스 라벨 사이의 상관은 모델의 인상적인 수치에 영향을 줄 수 있다. 외부 신
    호가 정보 누출처럼 동작할 가능성까지 배제하지 못한다.



 7. 결론 및 후속 과제
 공개 UCI 피싱 특징 표본 450개에서 같은 로지스틱 회귀를 사용한 결과, URL 표기 특징 8개에 비해 원본 30개 특징은 피싱 F1을
 0.688에서 0.914로 향상시켰다. 탐색적 SSL 추가 조건은 F1 0.875로, 차이의 상당 부분이 SSL 관련 특징의 존재와 함께 발생했
 다. 중복 제거 민감도 분석에서도 같은 방향이 관측되었다. 연구가설은 이 자료 범위에서 지지된다.

 후속 연구에서는 수집 시점이 기록된 최신 URL 데이터를 확보하고, 동일 도메인이 학습/시험에 교차하지 않는 분할, 시계열 외부시
 험, 클래스 불균형·비용 민감도 분석, 그리고 특징 수집 비용 측정을 함께 진행해야 한다. 이 과제는 재현 가능하게 제한된 질문에 답
 하는 데 목적이 있으며, 현재의 탐지 운영 성능을 보증하지 않는다.



 8. 실험 재현 방법
 제공된 ZIP 안의 `reproduction/` 폴더에서 Python 3.13 환경을 준비하고 다음 명령어를 실행한다. 패키지의 450건 원자료를 사
 용하는 기본 재현은 네트워크 연결이 필요하지 않다.

 1. `python -m pip install -r requirements.txt`

 2. `python run_analysis.py`

 3. `python sensitivity.py`

 4. `results/metrics.json` · `results/sensitivity_deduplicated.json` · `results/out_of_fold_predictions.csv`의 값과 그
 림 2개를 비교한다.

 verify_source_sample.py --source "Training Dataset.arff"`를 실행한다. 이 추가 검증은 원본 파일이 따로 필요하다. 표본을
